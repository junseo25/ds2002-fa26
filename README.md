# DS2002 Fall 2026 — Data Science Systems

This repository is my chronological learning portfolio for **DS2002: Data Science Systems** at the University of Virginia. It contains my completed lecture notebooks, studios, and labs for Fall 2026.

The purpose of the repository is to document how my data-science workflow develops across the course—from setting up a reproducible environment and using GitHub to querying databases, cleaning tabular data, working with nested JSON, and responsibly retrieving data from APIs.

## Repository contents

| Folder | Topics covered |
| --- | --- |
| [`01-foundations`](notebooks/01-foundations/) | Computing environments, Git, GitHub, Colab/Kaggle workflows, reproducibility, and notebook submission practices |
| [`02-sql-databases`](notebooks/02-sql-databases/) | SQL fundamentals, filtering, aggregation, joins, grouping, and validation |
| [`03-pandas-cleaning`](notebooks/03-pandas-cleaning/) | DataFrames, Pandas operations, merging, data cleaning, missing values, duplicates, and quality checks |
| [`04-json-apis`](notebooks/04-json-apis/) | JSON structures, nested records, normalization, joins, public APIs, request failures, caching, and retries |

## Notebook structure

The notebooks are organized by course module and named using this convention:

```text
YYYY_MM_DD_Jun_Seo_Lee_—_Topic_—_Type.ipynb
```

Each notebook is labeled as a **Lecture**, **Studio**, or **Lab**. Completed notebooks retain their code outputs and include comments explaining the reasoning behind important steps and decisions.

## How to use this repository

1. Open a module folder and select a notebook by date.
2. Read the notebook directly on GitHub or use its **Open in Colab** badge.
3. Run the notebook from top to bottom to reproduce its results.

Some API notebooks use live public data, so individual response values may change when they are run again. The underlying workflow and validation steps should remain reproducible.
